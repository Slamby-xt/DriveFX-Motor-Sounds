# DriveFX on Vercel

Static site + license/payment API on Vercel, data in Upstash Redis (a database company; Vercel's Marketplace provisions and bills it, and injects the credentials as server-only environment variables).

## Layout
| Path | What |
|---|---|
| `public/` (generated by `tools/build-public.mjs`) | the only files served publicly: site, `admin/index.html`, images, `vendor/` |
| `api/index.js` | the single Vercel Function; `vercel.json` rewrites `/status /trial /prices /go /thanks /portal /stripe-webhook /grant /revoke /list /find /relink` to it |
| `server/handler.js` | all endpoint logic (ported from the old Cloudflare Worker, same behaviour) |
| `server/store.js` | Redis wrapper: key prefix, atomic counters, lock, scan |
| `tests/` | `npm test` (in-memory store + fake Stripe) |
| `worker/` | the OLD Cloudflare Worker, kept only for rollback; not deployed, not public |

Never public: `server/ api/ tools/ worker/ tests/ _ad/ docs/` and any `.env*` file (the build script copies an explicit allow-list into `public/`).

## Environment variables (server-only)
`STRIPE_KEY`, `STRIPE_WEBHOOK_SECRET`, `ADMIN_TOKEN`, `TRIAL_PEPPER`, `DATA_PREFIX` (`prod` | `sandbox`), optional `TERMS_CONSENT`, `TAX`; Redis: `KV_REST_API_URL`, `KV_REST_API_TOKEN` (+ `KV_URL`, `REDIS_URL`, `KV_REST_API_READ_ONLY_TOKEN`, injected by the integration). Placeholders in `.env.example`.

## Environment separation
* Production deployment: live Stripe key, `DATA_PREFIX=prod`. Preview/Development: Stripe **test** key, `DATA_PREFIX=sandbox`.
* The free Upstash plan gives one database, so both share it and are separated by a **key prefix** (`prod:` / `sandbox:`). It is enforced in `server/store.js` (`checkIsolation`): a live key with a non-prod prefix, a test key with the prod prefix, or a Production deployment without `prod` makes every API call fail with 503 instead of touching data.
* To get fully separate databases later, create a second Upstash database and connect it to Preview/Development only.

## Data model (all keys start with `prod:` or `sandbox:`)
| Key | Value | TTL |
|---|---|---|
| `lic:<DFX-ID>` | JSON `{exp, iat, days, plan, src, sub, cus, cuss[], pi, cancel, ended}`; `exp` 0 = lifetime | none |
| `cus:<stripe customer>` | device ID | none |
| `pi:<payment intent>` | device ID (lifetime purchase already applied) | none |
| `ev:<event id>` | `p` (in progress) / `d` (done): webhook idempotency | 120 s / 7 days |
| `tr:id:<hash>`, `tr:dev:<hash>` | JSON `{used, at}` trial seconds (keyed hashes only) | 400 days |
| `tr:net:<hash>` | counter of new trials per network per day | 2 days |
| `rl:admin:<ip>`, `rl:go:<ip>` | rate-limit counters | 15 min / 1 h |
| `lock:license` | short lock serialising license changes | 30 s |

Atomicity: counters use an `INCR` script; trial usage uses a "keep the maximum" Lua script; license/customer/purchase changes run under the lock; webhook events are claimed with `SET NX`.

## Inspect / administer the data
* Admin panel `https://drivefx.pro/admin` (list, grant, extend, revoke, find by email, move to new ID).
* Vercel dashboard > Storage > the Upstash database > Data browser (or "Open in Upstash"), or `npx vercel integration open upstash drivefx-licenses`.
* Backup/export: Upstash console > database > Backup (daily backups are a paid feature); free option: `GET /list` as admin (copy the JSON), or the Upstash "Export" in the data browser. Webhook data is also re-creatable from Stripe.
* Free-tier limits (check Upstash for the current numbers): a monthly command budget, a size cap and one free database; DriveFX uses a handful of commands per visit/payment. Upstash e-mails before limits are hit; upgrading is a deliberate click, nothing is upgraded automatically.

## Admin password
Use a long random `ADMIN_TOKEN` (32+ characters recommended; 14 is the enforced minimum). Wrong logins are limited to 8 per network per 15 minutes; after 50 wrong logins from anywhere each further failure is slowed (up to 3 s). A correct password is never locked or delayed by other people's failures.

## Stripe
* Webhook URL: `https://drivefx.pro/stripe-webhook` (no redirect; apex is the canonical host). Events: `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `invoice.paid`, `invoice.payment_failed`, `customer.subscription.updated`, `customer.subscription.deleted`, `charge.refunded`, `charge.dispute.created`.
* The signing secret of the deployed endpoint goes in `STRIPE_WEBHOOK_SECRET` (never the `stripe listen` one).
* Products/prices/portal: `node tools/stripe-setup.mjs` (sandbox) or `--live`; safe to re-run.
* API version pinned: `2026-02-25.clover` (`server/handler.js` and `tools/stripe-setup.mjs`).

## Client-side enforcement limits (unchanged by Vercel)
The Free/Pro gating runs in downloaded JavaScript (`paywall.js`) and works offline. Anyone who edits that code can unlock Pro features locally, and clearing browser data on a new device/network gives a new trial. The server only records trial usage and licenses; hosting on Vercel does not make the code tamper-proof.

## Deploy / rollback
* Deploy: `npx vercel deploy --prod` (or push to `main`, the project is connected to GitHub).
* Roll back a deployment: Vercel dashboard > Deployments > previous one > Promote, or `npx vercel rollback`.
* DNS rollback: see the table in the migration report (previous values: apex `A` 185.199.108.153 / .109.153 / .110.153 / .111.153, `www` `CNAME` slamby-xt.github.io.). GitHub Pages and the Cloudflare Worker stay up until removed by hand.
